Ce que cette démo illustre

Le standard spécifie les propriétés attendues. Le runtime applique les règles résolues.

Cette page situe les responsabilités. Elle ne transforme ni une configuration admissible en garantie de déploiement, ni une simulation en preuve d'effet chez un fournisseur réel.

DEUX LECTURES COMPLÉMENTAIRES

Les couches situent les responsabilités. La boucle explique la production de preuve.

Le diagramme d'observation sert de grille de lecture : relier la question, le profil, les observations, l'interprétation et la restitution. Le rapport propose huit étapes de lecture, avec accès aux champs source de chaque preuve et des explications documentaires identifiées.

Le fil conducteur du parcours

Question → profil → observations → décision → trace → restitution

Les champs signés restent des données source. Les explications d'architecture sont du contexte documentaire. La signature locale atteste le record de simulation, sans constituer une attestation indépendante.

Trois dépôts, trois rôles.

Les sources de l'écosystème donnent le contexte technique de cette démo. Elles ont été consultées en lecture seule ; leur code n'est pas exécuté par ce dépôt local.

Catalogue structurel, profils, propriétés attendues et contrats. L'admissibilité d'une configuration reste distincte d'une capacité démontrée.

Harnais de conformance et scénarios adversariaux. Un résultat de test du harnais ne valide pas, à lui seul, un déploiement de production.
